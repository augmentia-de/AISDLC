# Tools - where are they?

The project has three types of tools. They belong in **three** places, and every place
has a clear rule. This prevents the hodgepodge of tools that would otherwise arise
when an agent puts a new script next to it at every opportunity.

| Type | Location | Rule |
|---|---|---|
| **Phase Tool** | `.agent/tools/` | Helps a *step* of the AI-SDLC, not part of the application. Loaded by the framework agent. |
| **Code Generator** | `src/<module>/tools/` | Generates code from a source (contract, schema). Belongs next to the code it generates. |
| **Project Specifics** | `src/<module>/tools/` | Like code generator. |

## What is currently there

| File | Type | Source |
|---|---|---|

**The framework only contains what is stack-independent.** A generator that creates the stories
Generated by *this* project, it is project specific and does not belong here - it belongs
into the project (see `src/<modul>/tools/`) or is done by the skill
Replaced `aisdlc-prd-to-stories` which returns the **method** instead of the result.

##Rules

1. **A tool has exactly one place.** A phase tool **doesn't** belong in
   `docs/` — `docs/` is the requirements specification that a human reads. A
   Generator that lies there becomes part of the specification and not of anyone
   executed.
2. **Phase tools are framework infrastructure** and are located at `.agent/tools/`.
   They are co-versioned because they define the step, not the application.
3. **Code generators lie next to their code.** A generator that generates Java models
   generated belongs in the backend - it is used there together with the build.
4. **A generator has exactly one source of truth.** `generate-contract-roles.py`
   reads `x-required-role` from the contract; the roles are not in two places
   maintained.
5. **No generator without a comment in the docstring explaining why.** The
   Docstring answers: from which source, where, and why it is this source
   needs.needs.
6. **A tool that writes files checks its result.** The vendor run
   After copying, compares each file from the source with the target and breaks with it
   Exit 1 if something is missing. Otherwise, a silent partial vendoring will only be noticed
   if a skill points into space when reading.

##Call
```
bash
# Konsistenz der Traceability-Kette pruefen
python3 .agent/tools/traceability_check.py

# Beleg erzeugen (schreibt .agent/artifacts/traceability.md und -fill.md)
python3 .agent/tools/traceability_check.py --fill
```

can. A made-up path is worse than a gap — it looks and is occupied
